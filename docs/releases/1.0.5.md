# 1.0.5 — global class labels in translated Elementor kits

Released 2026-10-03. This update fixes the demonstrated case where embedded translated templates render technical global class IDs instead of the labels used by the source kit's CSS. The four text-translation filters are unchanged from 1.0.4.

## Behavior

After Elementor's native class transformer, resolve only remaining global IDs through an explicit source Kit. Require published kits, verified source identity and bidirectional WPML association with the configured active kit. Preserve native resolved names, local classes and target declarations in labels, order or class post IDs, including incomplete declarations. Unknown or ambiguous contracts remain unchanged.

Editor/preview, admin, REST, AJAX and CLI requests are excluded. The fallback does not write metadata, switch language, replace the active kit, change saved Elementor data or regenerate CSS. It uses no site-specific IDs or class names.

## Limits and removal

- Acceptance covers the demonstrated class-resolution failure on one stack. Repeat before/after translation and computed-style checks on every deployment; a class label alone does not prove the expected stylesheet is loaded.
- No real form submission was performed. Submission actions, email delivery and integrations are not certified by this release test.
- The native import regression reused existing translations. New source-edit/reordering cycles and the full explicit-override/inherited-value matrix were not repeated for 1.0.5; earlier tests of those behaviors belong to the separate [1.0.4 record](1.0.4.md). Editor/preview exclusion, target-owned classes and unknown-contract behavior are covered synthetically, not claimed as new exhaustive live cases.
- The historical origin of incomplete translated-kit metadata remains unverified. The controlled 1.0.4 toggle did not demonstrate an immediate rendering regression caused by that adapter.
- Native omission of some numeric XLIFF units, general inherited-default resolution and untested component/editor workflows retain their existing limits.
- After native support improves, deactivate the plugin on the actual stack and verify fresh translation cycles plus global-class rendering before removing it. It owns no persistent data; the label fallback is no longer applied when it is inactive.
