# 1.0.4 — native WPML compatibility for V4 component and form text

Released 2026-10-02. This is the first public update after 1.0.1; 1.0.2 and 1.0.3 were development candidates, whose fixes are included here.

## What changes

- Keep the original adapter for explicit component text overrides stored as `escaped-html`.
- Expose wrapped form names through `form-name>value`, preserving WPML's native `form-name` identity and existing scalar registration.
- Adapt direct exposed heading/paragraph master origins in memory, delegating extraction and import to WPML and restoring their original type.
- Delegate typed select-option labels through WPML's native item handler. Temporary collection aliases and IDs derived from unique technical values keep duplicate labels distinct after source edits and reordering. Technical option values remain unchanged; no temporary data is persisted.

Native extraction/import probes bypass component, master and select adaptation when the supported native contract works. Form-name protection checks registration, not a runtime round trip. Unknown/custom contracts and unsafe import results are left unchanged. There are no independent translations, direct destination writes or speculative registry synchronization.

## Boundaries

- The zero select label is returned by local item extraction tests but absent from live XLIFF. Native import preserves it in stored data and rendering. This release does not claim that a live zero translation unit was exported.
- Elementor drops the submitted blank option during source saving, leaving four persisted rows. Five-row local fixtures cover a blank row; the live cycles do not certify WPML handling of a persisted blank row.
- Missing target component registry metadata caused no frontend defect in the tested fixture. General inherited-default resolution, null/forwarded-binding resolution, registry synchronization and untested editor workflows are not added or certified.
- Native master-text omissions of empty text and literal `"0"` remain unchanged. Other component properties, form controls/actions and unknown contracts remain outside scope.
- A passing cycle on one stack is not universal compatibility certification. Repeat before/after translation checks and fresh export/import/render cycles on each deployment.
